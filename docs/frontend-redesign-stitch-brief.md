# kNews 前端美化重设计说明（供 Stitch 使用）

## 1. 项目目标与硬约束

### 目标
- 在不改动现有后端逻辑、接口语义、权限判断、数据流的前提下，对当前项目前端进行完整视觉升级。
- 保留现有全部功能，不缺失登录、订阅、AI 对话、热点浏览、设置、后台管理等能力。
- 提升桌面端质感，同时保证移动端可用。
- 输出可直接交给 Stitch 的页面设计说明与统一视觉方向。
- 我会给出现在的前端界面图片，辅助你理解。

### 不可变约束
- 只做前端美化与交互优化，不改 Electron 主进程逻辑，不改 IPC 协议，不改数据库字段语义。
- 所有现有页面都必须保留入口与功能闭环。
- 权限相关逻辑保持原样：
  - `/assistant` 需登录后访问。
  - 管理后台模块仅管理员可见。
  - 订阅等级会影响一键刷新、MCP 权益、后台管理能力。
- 不能因为重设计牺牲以下能力：
  - 首页多看板浏览
  - 数据源关注/拖拽排序/刷新
  - 登录弹窗与 GitHub Device Flow
  - 订阅升级
  - AI 对话流式输出、热点卡片、思考态
  - MCP Key 管理
  - 后台用户、数据源、API Key、权益配置

### 当前技术背景
- 技术栈：Electron + Vue 3 + Pinia + Vue Router + Element Plus + UnoCSS + 自定义基础组件
- 当前主题机制：`system / light / dark`
- 当前全局风格：浅色底 + 轻渐变背景 + 蓝色交互主色

## 3. 建议的整体视觉方向

### 设计关键词
- 专业新闻终端
- 高密度但不压迫
- 桌面产品感
- 信息优先
- 数据可视化友好
- AI 能力独立且高级

### 建议风格总纲
- 首页与阅读端采用“科技媒体终端”风格：
  - 雾面玻璃卡片
  - 浅层渐变背景
  - 明确的板块分区
  - 强调信息层级与扫描效率
- AI 助手页采用“沉浸式工作台”风格：
  - 左侧会话栏 + 中央对话流 + 底部输入工作区
  - 热点卡片更像情报摘要卡
- 后台管理页采用“专业 SaaS 控制台”风格：
  - 可参考 `new-api` 的控制台组织方式
  - 强化筛选栏、统计卡、表格、抽屉/弹窗、图表
  - 保持企业后台气质，但视觉上更干净、更现代

### 色彩建议
- 主品牌色：深海蓝 / 电光蓝
- 辅助色：青绿、橙金、玫红仅作强调
- 背景：
  - 浅色主题：暖灰白 + 低饱和蓝雾渐变
  - 深色主题：石墨黑 + 蓝青漫反射
- 状态色：
  - 成功：绿
  - 警告：橙
  - 危险：红
  - 信息：蓝

### 字体建议
- 中文：更现代、更有科技感的无衬线
- 英文与数字：建议单独使用更利于数据展示的数字字体/等宽字体
- 标题更有张力，正文偏克制

### 动效建议
- 页面切换：轻量淡入 + 位移
- 卡片悬停：阴影抬升 + 边框高亮
- 排行榜/热点卡加载：骨架屏 + 渐显
- AI 流式输出：保留光标闪烁、思考态展开收起

## 4. 页面逐页说明

## 4.1 全局 App Shell

### 当前功能
- 顶部包含品牌、首页 tab、AI 入口、主题切换、一键刷新、登录/用户菜单
- 提供移动端抽屉和底部导航
- 承载全局命令面板、Toast、登录弹窗、GitHub 验证弹窗

### 设计建议
- 顶栏做成“悬浮工作台式 Header”
- 左侧是品牌，中间是当前内容导航，右侧是快捷动作和账户区
- 一键刷新做成更强 CTA，但要明确等级限制状态
- 登录按钮、头像菜单、订阅等级标签做成统一账户胶囊

## 4.2 首页 `/`

### 页面定位
- 核心首页
- 承担热点总览、实时追踪、关注源浏览、更多分类浏览
- 是整个产品最重要的主工作台

### 页面结构
- 顶部 tab：
  - 热点
  - 时事
  - 关注
  - 更多
- `更多` tab 提供：
  - 数据源搜索
  - 分类筛选
  - 重置筛选
- 主体区域是多列信息看板网格
- 每个看板代表一个数据源

### 首页数据源看板 `source-board`
- 数据源 icon、名称、标签
- 更新时间
- 刷新按钮
- 关注/取消关注
- 新闻排行榜列表
- 排名变化、热度、附加 icon
- 支持拖拽排序
- 支持骨架屏

### 首页交互要点
- 首屏加载时展示 8 个骨架板块
- 滚动触发继续加载更多板块
- 看板可拖拽重排
- 支持关注源持久化
- 支持本地和远端偏好同步
- 通过 query 参数控制 tab

### 当前体验特征
- 已经具备不错的信息密度
- 卡片式看板方向正确
- 视觉统一性比后台页更强

### 待优化点
- 看板高度较高，但内部信息节奏还能更高级
- 排名、热度、状态的视觉语义可以更精细
- 缺少首页级“信息节奏控制”，比如头部摘要、当日重点、筛选状态条
- `更多` 模式和普通 tab 的视觉切换还不够有仪式感

### Stitch 设计要求
- 首页必须保留多看板信息架构，不要改成单栏 feed
- 看板仍需支持：
  - 刷新
  - 关注
  - 拖拽排序
  - 点击标题跳转原始链接
- 建议把首页做成“情报矩阵”：
  - 顶部有轻摘要
  - 中部是主看板矩阵
  - 看板内强调排名、状态、热度
- 可以增加：
  - 今日热点摘要条
  - 当前筛选面包屑
  - 数据更新时间总览

## 4.5 AI 助手页 `/assistant`

### 页面定位
- K-Ai 对话助手
- 融合问答、热点摘要、流式输出、思考过程、历史会话

### 页面结构
- 左侧：
  - 新对话按钮
  - 历史记录列表
- 右侧：
  - 顶部状态栏
  - 消息流区域
  - 空状态
  - 底部输入区域
  - 首屏热点问题 chips

### AI 消息特殊结构
- 助手消息可以包含：
  - 热点速览卡
  - Markdown 文本
  - 状态行
  - 思考中面板
  - 流式输出中的暂态内容

### 关键能力不能丢
- 历史会话切换
- 新建会话
- 删除会话
- 用户消息与助手消息双边布局
- 热点卡点击打开外部链接
- 流式回答
- 思考态展开/收起
- 停止生成
- 滚动到底部

### 当前优点
- 功能完整度非常高
- 已有明显类 ChatGPT 的交互基础
- 热点卡与普通对话结合是产品亮点

### 当前问题
- 视觉上仍偏“实现完成”，未到“产品完成”
- 热点卡、状态线、思考块之间的层级关系可更清晰
- 空状态可以更有引导性
- 输入区还可做得更高级、更像工作台

### Stitch 设计要求
- 整体方向参考“高级 AI 工作台”
- 左侧会话栏要更有组织性
- 右侧聊天区要更沉浸、更清晰
- 热点速览卡要设计成真正的“新闻 intelligence card”
- 思考态与生成态要有明确但克制的视觉差异

## 6. 设计系统建议

### 圆角
- 主卡片：16px 到 20px
- 次级卡片：12px 到 16px
- 按钮：10px 到 14px
- 标签/胶囊：999px

### 阴影
- 首页卡片：柔和、扩散型阴影
- 后台卡片：更克制，强调边框和层级
- 弹窗：更深更聚焦

### 边框
- 默认边框较轻
- Hover / Active / Focus 用更高对比蓝色描边

### 信息密度
- 首页：高密度，但每个看板内部保持清晰留白
- AI 页：中密度
- 后台页：高密度，以表格和图表为核心

---

## 7. 后台管理界面参考方向（结合 new-api）

### 可借鉴点
- 控制台式布局
- 顶部筛选栏 + KPI 卡 + 列表/表格 + 弹窗/抽屉
- 数据分析页中图表与排行榜并置
- 管理页按钮样式偏克制，不抢主体数据注意力
- 信息结构上强调“筛选 > 结果 > 详情”

### 本项目后台推荐吸收方式
- 数据源页：吸收它的“筛选 + 网格/列表管理”节奏
- 用户页：吸收它的“表格主导 + 明细弹层”思路
- API Key 页：吸收它的“KPI + 趋势 + 明细”的 SaaS 组织方式
- 权益页：吸收它的“配置表单清晰直给”风格

### 不建议直接照搬的点
- 本项目是桌面新闻产品，不是纯 API 网关产品
- 视觉上仍需保留媒体产品与 AI 助手的品牌气质
- 首页与 AI 页必须比传统后台更具品牌识别度

## 10. 最终结论

- 当前项目前端功能骨架已经较完整，尤其首页、AI 助手页、MCP 设置页、后台 API Key 管理页具备较高可塑性。
- 重设计时建议采用“双核心”策略：
  - 面向用户的首页/阅读/订阅/AI 页强调品牌和体验
  - 面向管理的设置/后台页强调控制台效率和信息清晰度
- 全部改造应坚持一条原则：
  - 只升级视觉与交互表达，不动既有后端逻辑，不减少任何现有功能。
