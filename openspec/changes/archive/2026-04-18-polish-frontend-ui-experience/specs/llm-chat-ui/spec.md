## MODIFIED Requirements

### Requirement: 消息发送与展示
用户发送消息后，系统 SHALL 立即显示用户消息，禁用重复提交，并展示 assistant 等待状态。在当前单客户端单流架构下，如果已有流式响应在进行，系统 MUST 阻止新的发送或会话切换类操作，并给出明确提示。

#### Scenario: 发送消息并等待回复
- **WHEN** 用户输入文本并点击发送
- **THEN** 系统立即在消息流中显示用户消息气泡，禁用发送按钮，显示 assistant 加载指示器

#### Scenario: 收到回复
- **WHEN** assistant 回复成功返回
- **THEN** 系统追加 assistant 消息到消息流，自动滚动到最新消息，恢复发送按钮

#### Scenario: 回复失败
- **WHEN** GLM API 请求失败（超时、鉴权失败等）
- **THEN** 系统在消息流中显示用户可理解的错误提示，不丢失已有消息

#### Scenario: 单客户端单会话保护
- **WHEN** 当前已有流式响应在进行，用户再次尝试发送消息、新建会话、切换会话或删除会话
- **THEN** 系统 MUST 阻止该操作，并显示错误提示“为了减缓llm请求压力，每个客户端仅支持同时一个会话。”

### Requirement: 删除会话
用户 SHALL 能删除历史会话，但删除前 MUST 经过二次确认，避免误删。

#### Scenario: 删除前确认
- **WHEN** 用户点击某个历史会话的删除按钮
- **THEN** 系统 MUST 先弹出确认提示，包含当前会话标题或等价识别信息，并明确说明该操作不可撤销

#### Scenario: 确认删除会话
- **WHEN** 用户在确认提示中选择继续删除
- **THEN** 系统从会话列表移除该会话，删除持久化记录，如果删除的是当前会话则切换到最近一个会话或新建空会话

## ADDED Requirements

### Requirement: 热点速览卡强化来源识别
K-Ai 助手中的热点速览卡 SHALL 使用来源主题色强化来源识别，同时保持现有卡片结构和阅读顺序不变。

#### Scenario: 序号块跟随来源主题色
- **WHEN** 系统渲染热点速览卡中的新闻条目序号
- **THEN** 序号块 MUST 使用对应来源的主题色作为背景，并自动保证文字对比度可读

#### Scenario: 不增加无意义装饰标记
- **WHEN** 系统渲染热点速览卡头部
- **THEN** 页面 MUST 不显示与内容无关的装饰性英文角标，例如 `INTELLIGENCE`

### Requirement: 助手消息区保持紧凑阅读节奏
助手消息区 SHALL 在热点卡片、正文和输入区之间保持紧凑且稳定的阅读间距，避免出现明显空白带或消息离输入框过远。

#### Scenario: 热点卡片与正文分隔清晰
- **WHEN** 热点速览卡后紧跟正文内容
- **THEN** 系统 MUST 在卡片与正文之间保留清晰但不过大的间距

#### Scenario: 最后一条消息贴近输入区
- **WHEN** 消息记录过多并出现滚动
- **THEN** 用户滚动到列表底部时，最后一条消息 MUST 与输入区保持合理安全距离，不得留下过大的底部空白

#### Scenario: assistant 气泡不出现固定空白宽度
- **WHEN** assistant 回复内容较短
- **THEN** 消息气泡 MUST 随内容宽度自然收缩，不得因为固定宽度在右侧形成明显空白区域
